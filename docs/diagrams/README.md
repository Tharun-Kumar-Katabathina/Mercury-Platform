# Mercury diagrams

Interactive diagrams of the platform, generated with [Archify](https://github.com/tt-a1i/archify) from typed JSON.
Each `.html` file is self-contained: open it in a browser (no server, no network).

| Diagram | Source | What it shows |
|---|---|---|
| [Architecture](mercury-architecture.html) | `mercury-architecture.json` | Gateway, services, Kafka, Redis, Qdrant; REST versus Kafka paths |
| [ASYNC order reservation](mercury-async-order-sequence.html) | `mercury-async-order-sequence.json` | 202 accept, reserve command, reply, event, deadline fallback ([async-reservation.md](../async-reservation.md)) |
| [Order saga lifecycle](mercury-order-saga-lifecycle.html) | `mercury-order-saga-lifecycle.json` | Saga states and transitions ([saga-recovery.md](../saga-recovery.md)) |

## Using the viewer

`?` guide · `/` find a node · `R` probe a route · `L` compare roles · `T` theme · `E` export (PNG, SVG, ...).

## Regenerating

The JSON files are the source of truth; the HTML is generated. After changing a JSON file, run from the repository root:

```bash
node <archify>/archify/bin/archify.mjs finalize <type> docs/diagrams/<name>.json docs/diagrams/<name>.html --quality showcase --json
```

`<type>` is `architecture`, `sequence` or `lifecycle`. `finalize` validates the JSON, renders the HTML and runs a real-browser check (it needs Chrome); a non-zero exit means a gate failed and the message says how to repair it.

## Accuracy

These diagrams were authored from `docs/*.md`, `docker-compose.yml`, the gateway routes, the Kubernetes manifests and the saga enums, not generated by scanning code. If the platform changes (a new service, a new Kafka topic, a new saga state), update the JSON and re-run `finalize`. They carry no per-node source references because this checkout has no `origin` remote, which Archify's evidence mode requires.
